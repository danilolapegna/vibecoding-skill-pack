# Install Guide

> How to drop the Vibecoding Skill Pack into an existing Claude Code project, or into a new one.

## Default install (recommended)

```bash
git clone https://github.com/danilolapegna/vibecoding-skill-pack.git
cd your-project
mkdir -p .claude
cp -R ../vibecoding-skill-pack/.claude/. ./.claude/
```

The same command upgrades an existing install **by overwriting files with matching names**. Back up local changes and resolve conflicts before copying. The trailing `/.` matters: with GNU `cp` (Linux, WSL, Git Bash), `cp -r pack/.claude/ ./.claude/` nests the pack in `.claude/.claude/` when `.claude/` already exists, and the old version stays active.

Claude Code automatically discovers the skills in `.claude/skills/` and the rules in `.claude/rules/`. No further configuration needed.

## Verify install

In Claude Code:

```
list skills
```

Should output (among others):

```
- vibecoding-engineer
- engineering-brief
- codebase-onboarding
- delivery-readiness-audit
```

## Install just the skill files with the skills CLI

If you want to choose a coding agent's skill directory, the open-source [skills CLI](https://github.com/vercel-labs/skills) can install the four skills directly. This route requires Node.js 22.20 or later. Run it from the project where you want to use the pack, after reviewing any existing skills with the same names: matching files can be overwritten.

```bash
DISABLE_TELEMETRY=1 npx --yes skills@1.7.4 add danilolapegna/vibecoding-skill-pack --skill '*' --agent claude-code --yes --copy
```

The command downloads the public repository from GitHub and copies the four skills into `.claude/skills/`, including the delivery audit's `references/mechanical-verification.md`. It does not install Agent Code Gates, Deep Smoke or Git hooks. The environment setting disables the CLI's anonymous install telemetry and security-audit requests for this run; it does not prevent the download from GitHub or npm.

**This route does not copy the three always-on rules in `.claude/rules/`.** Use the default copy method above when you want the complete Claude Code pack, including those rules. If you keep a skills-only install, open the rules in the repository before deciding what your project still needs.

For Codex, replace `--agent claude-code` with `--agent codex`; the CLI places the skill files in `.agents/skills/`. Both file-install routes were tested with CLI 1.7.4. This checks file delivery, not whether either agent follows the instructions, and does not translate Claude Code-specific conventions. The full workflow documented in this pack remains the Claude Code workflow.

After installing, check that all four `SKILL.md` files and the audit reference exist. If a skill is missing, stop and read the CLI output rather than treating a successful command alone as a complete install. To remove a trial, remove only the four skill directories that this command created; keep any pre-existing files you need.

## Selective install (one skill only)

If you only want `vibecoding-engineer` without the chain dependencies:

```bash
mkdir -p your-project/.claude/skills
cp -r vibecoding-skill-pack/.claude/skills/vibecoding-engineer your-project/.claude/skills/
```

Note: `vibecoding-engineer` declares `engineering-brief` and `delivery-readiness-audit` as Mandatory chain. Without them, the skill will flag them as "pending" in every deliverable. The selective install is fine for evaluation but the full pack is recommended for actual use.

## Conflict resolution (existing skills with same name)

If your project already has a skill with one of the same names:

1. **Rename ours**: move our skill to `.claude/skills/vibecoding-engineer-public/` and update the chain references in our other skills accordingly
2. **Rename yours**: move your existing skill to a different name first
3. **Merge**: read both SKILL.md files and consolidate manually (advanced)

The copy command overwrites matching paths. Resolve conflicts before running it; the pack has no installer that merges your changes.

## Project context (optional but recommended)

For the skills to produce high-quality output, populate a `context/` folder in your project:

```
your-project/
├── .claude/                     # the skill pack (copied above)
├── context/
│   ├── product-spec.md          # MANDATORY for vibecoding-engineer
│   ├── technical-architecture.md
│   ├── codebase-state.md        # generated by codebase-onboarding
│   └── (other optional files)
└── (your code)
```

Without `context/product-spec.md`, `vibecoding-engineer` will pause and ask you for one before generating prompts. This is intentional: without spec, prompts become generic and produce fragile code.

## Test the install with the examples

```bash
cd your-project
ls ../vibecoding-skill-pack/examples/
# 01-orchestrator-prompt/
# 02-feature-prompt-with-fm-coverage/
# 03-mechanical-verification/
```

Read the first two examples' `source.md` files to see full prompt templates (with `## Anti-pattern blocked` and `## Test gate suggested` sections).

The third example has its own [README and executable tests](examples/03-mechanical-verification/README.md). Its Node dependencies are optional and local to that example. The default `.claude/` copy also includes the audit's `references/mechanical-verification.md`, so the workflow remains available in your project without installing either program or any hook.

## Uninstall

```bash
cd your-project
rm -rf .claude/skills/vibecoding-engineer
rm -rf .claude/skills/engineering-brief
rm -rf .claude/skills/codebase-onboarding
rm -rf .claude/skills/delivery-readiness-audit
rm .claude/rules/skill-chaining.md
rm .claude/rules/skill-design-invariants.md
rm .claude/rules/mechanical-gates-over-advisory.md
```

(Leave `.claude/` itself in place if you have other custom skills.)

## Version compatibility

- **Claude Code**: tested on v2.1+ (skill discovery from `.claude/skills/`)
- **Cursor**: SKILL.md files are readable as documentation but auto-invocation requires Claude Code
- **Devin / Copilot Workspace**: same caveat

The skill pack is documented in pure markdown with no proprietary syntax, so the skills are portable to any AI coding assistant that supports skill discovery from a folder.
