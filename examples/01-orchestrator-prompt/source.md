# Example 01: Agentic Orchestrator Prompt (full FM-XX coverage)

> Real prompt template generated by `vibecoding-engineer` for an agentic orchestrator that invokes N skills to produce automated deliverables. Shows the canonical format with all sections including `## Anti-pattern blocked` and `## Test gate suggested`.

## Contesto

Stack: Vite + React + TypeScript + Postgres + serverless edge functions.
Architettura: agentic AI orchestrator che invoca N skill per generare deliverable autopilot. Single resource user, multi-resource registry.
Vincoli infra: row-level security on DB, no admin credentials in client, env vars in secret manager.

## Requisito

REQ-ORC-002: l'orchestrator deve invocare skill in sequenza goal-aligned. Ogni skill emette artefatti che il prossimo step usa. L'orchestrator NON deve girare in tondo invocando skill senza scopo.

## Vincoli

- OWASP Agentic ASI01 (Agent Goal Hijack): orchestrator non puo accettare goal redefinition runtime
- OWASP Agentic ASI06 (Memory & Context Poisoning): artifact validation schema prima del persist
- Rate limit: max 30 skill invocations per user-resource per 24h
- Budget: max 50k tokens per orchestrator run, soft cap (not hard-cut)

## Anti-pattern blocked

- **FM-01**: orchestrator non gira in tondo. Ogni skill invocata DEVE loggare `goal_alignment_score` (numerico 0-1), audit periodico abortisce la run se avg(score) < 0.6 sui ultimi 5 step.
- **FM-02**: stop conditions non sono hard-cut budget. Stop = quality_gate raggiunto OR user_paused=true OR error_rate > 0.3.
- **FM-04**: skills sono runtime-discovered via capability registry, no hardcoded skill list. Aggiungere skill nuova non rompe orchestrator existing.
- **FM-05**: lock atomico (user_id, resource_id) prima di avviare orchestrator run. Run parallele sullo stesso (user, resource) sono interrotte pulitamente.

## Output atteso

- `src/orchestrator/goal-aligned-orchestrator.ts` (logica core)
- `src/orchestrator/types.ts` (schema artifact + goal_alignment_score field)
- `src/orchestrator/capability-registry.ts` (skill discovery runtime)
- `db/migrations/<YYYYMMDD>_orchestrator_run_lock.sql` (lock table)
- `tests/orchestrator/orchestrator-goal-filter.test.ts` (test gate FM-01)
- `tests/orchestrator/stop-conditions.test.ts` (test gate FM-02)
- `tests/orchestrator/capability-registry-discovery.test.ts` (test gate FM-04)
- `tests/orchestrator/concurrent-run-lock.test.ts` (test gate FM-05)

## Criteri di accettazione

- [ ] Ogni skill invocation logga `goal_alignment_score` (numerico 0-1) in `orchestrator_run_steps` table
- [ ] Audit job legge log e abortisce run se `AVG(goal_alignment_score) < 0.6` sui ultimi 5 step
- [ ] Stop condition: NOT hard-cut su token cap. Stop = `(quality_gate=true) OR (user_paused=true) OR (error_rate > 0.3)`
- [ ] Skill nuova aggiunta via `capability_registry.register(skillId, metadata)`, no rebuild orchestrator
- [ ] Lock atomico via `SELECT FOR UPDATE` su `orchestrator_runs(user_id, resource_id)` row, second concurrent run riceve `ConcurrentRunError` e interrompe pulitamente
- [ ] Test gate FM-01, FM-02, FM-04, FM-05 verdi in CI
